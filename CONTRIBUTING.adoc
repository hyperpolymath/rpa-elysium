= Contributing to RPA Elysium

We welcome contributions! Please read this guide before submitting.

== Development Setup

[,bash]
----
# Clone the repository
git clone https://github.com/hyperpolymath/rpa-elysium.git
cd rpa-elysium

# Build and test
just check   # fmt + lint + test
just build   # Release build

# Or individually
cargo build --locked --workspace
cargo test --locked --workspace --all-targets
cargo clippy --locked --workspace --all-targets -- -D warnings
----

== Language Policy

This project follows the Hyperpolymath Language Policy (see `.claude/CLAUDE.md`):

[cols="1,1"]
|===
|Allowed |Use Case

|*Rust*
|Core framework, WASM, CLI

|*AffineScript*
|Future management console (not implemented)

|*Gleam*
|Backend services (BEAM)

|*Bun / Deno / pnpm / npm*
|JS runtime/tooling preference, in that order

|*Idris2*
|ABI definitions

|*Zig*
|FFI implementation

|*Bash*
|Scripts, automation
|===

*Banned for new application code*: TypeScript, ReScript, Go, Python, Java, Kotlin, Swift.
Do not add runtime tooling to this Rust workspace without a real use case.

== Pull Request Process

. Fork the repository and create a feature branch
. Ensure `just check` passes (fmt, lint, test)
. Code/config/scripts use `MPL-2.0`; prose uses `CC-BY-SA-4.0`
. All GitHub Actions must resolve to immutable commits in the reviewed actions.lock graph
. No banned language code introduced
. Submit PR against `main` with descriptive title and body

== Code Standards

* All source files must have SPDX license headers
* Run `just ci-check` for lock, community-health and regression controls
* Run `just audit` for the Cargo security audit
* Report exploitable vulnerabilities privately (link:SECURITY.adoc[security policy])
* All code must pass `cargo clippy -- -D warnings`
* All code must be formatted with `cargo fmt`
* Test coverage target: 80%+
* No hardcoded secrets, credentials, or API keys
* HTTPS only — no HTTP URLs

== Signed commits

Every commit that reaches the default branch must be signed; a ruleset refuses
unsigned pushes. Estate policy:
https://github.com/hyperpolymath/standards/blob/main/docs/SIGNING-POLICY.adoc[SIGNING-POLICY].

* **People and interactive agents** sign with an SSH key registered on GitHub
  as a *signing* key (`gpg.format=ssh`, `user.signingkey=<key>.pub`,
  `commit.gpgsign=true`). The committer email must be verified on that account.
* **Apps, bots and workflows** never `git push` local commits. They write
  through the API (`createCommitOnBranch` or the estate `signed-push` action)
  so that GitHub signs each commit.
* Merge PRs with **squash**. The ruleset checks every commit on the PR branch,
  not just the result, so one unsigned commit blocks the merge. Re-create such a
  branch with signed commits (`git cherry-pick -S`) and open a new PR.
  Rebase-merge replays commits unsigned and is disabled.
