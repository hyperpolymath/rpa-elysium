== Root causes and repairs

* The workflow YAML and lock already disagreed before #144: the Haskell setup
  action used `v2.12.1` while its lock used `v2.12.0`. CodeQL also had inherited
  ref drift. The lock now names the actual workflow refs and immutable commits.
* Most workflow files began with a generator management marker. The local
  linter required SPDX on the first line and failed 18 workflows. SPDX now
  precedes the marker; duplicate markers have been removed.
* The local language policy still banned Deno, contrary to the October 14
  Standards owner ruling. The policy now admits Bun, Deno, pnpm and npm in that
  order; the gate was not disabled.
* Governance was pinned to `fad242d35291de1898242d6737ba02b74a59a2f2`.
  That version installs a moving lock verifier and does not handle the newer
  verifier's no-external-ref/local-action findings. It now pins
  `c11c255e1b5546854e874d1486d61d6d5a4da29a`, the upstream #1250 compatibility
  fix that deliberately pins `gh-actions-lock v0.2.0`. The corresponding
  dependency record and transitive closure were updated together.
* An initial experiment with Standards `80014df...` passed lock verification,
  but introduced a new JS-runtime checker whose *build* failed with exit 101,
  before checking this repository. The repair deliberately selects the narrower
  verifier-compatibility commit above rather than disabling that new gate or
  declaring a failed check successful. Diagnosing that separate upstream build
  remains outside the validated compatibility rollout.
* Rust 1.99 clippy rejects the redundant `#[must_use]` generated by
  `async-trait 0.1.89`. Upstream commit
  `875ceecb100bab2cf369178633b4791336d92b75` removes the redundant attribute.
  Updating to `async-trait 0.1.92` (and its Syn 3 dependency) fixes the macro
  rather than suppressing `double_must_use` or dropping `-D warnings`.
* Changing Cargo dependencies activates the separate Cargo Audit workflow.
  Its newly exposed RUSTSEC-2026-0316 finding affects Wasmtime 36.0.15.
  Wasmtime and the coordinated Cranelift/Pulley packages now resolve to the
  patched 36.0.16 / 0.123.16 releases. Registry checksums were obtained from
  the crates.io index; GitHub's locked build and security audit validate the
  resulting graph.

== A red that is fiction, second mechanism: the push actor

`startup_failure` with zero jobs is usually read as a workflow-file problem. It
has a second cause, measured on this repository on 2026-10-14:

A pull request's head commit was created by the CodeRabbit app (its `Commit
suggestion` flow). GitHub created a run for every workflow on that head and
started none of them — `startup_failure`, no jobs, nothing to read — while the
`.github/workflows` tree at that commit was **byte-identical** to the preceding
head whose eight workflows all ran to success. Re-creating the same tree as a
commit authored by the repository owner started all eight normally.

Evidence: head `626d9df` (`actor=coderabbitai[bot]`, eight runs, all
`startup_failure`, zero jobs) versus head `2c851fa` (same tree, `actor` the owner,
all runs started). `gh run rerun` refuses: "cannot be rerun; its workflow file
may be broken."

So, before chasing YAML: if every workflow on one head failed to start and the
workflow tree is unchanged from a head that worked, check the run's actor

[source,bash]
----
gh api "repos/OWNER/REPO/actions/runs?head_sha=HEAD&per_page=10" \
  --jq '.workflow_runs[] | "\(.event) \(.actor.login) \(.conclusion)"'
----

and re-push the identical tree as a commit the repository's own identity
created. The repair is not to the workflows; it is to the head.

== Preventing recurrence

`check-lock-sync.sh` reads YAML through mikefarah/yq v4 and compares structured
job/step refs with jq. It no longer uses a GNU-awk line parser. It:

* handles quoted and flow-style workflows;
* ignores strings inside `run:` bodies;
* folds owner/repository case, but not tag/branch case;
* checks refs in both directions, including job-level reusable calls;
* rejects malformed refs, unsupported lock schemas, invalid dependency
  identities, non-immutable commits and dangling transitive edges;
* rejects lock entries for deleted workflow files;
* does not fabricate dependencies for zero-external-ref workflows;
* never modifies the workflows or lockfile.

Seventeen positive/negative regression controls run in the Lock Sync Gate.
`actions-lock-update-test.sh` additionally verifies observational verification,
rollback, malformed-verdict rejection and reusable-graph preservation.
Neither source code from a PR nor a PR-owned updater is executed under a
privileged `pull_request_target` workflow. There is no new bot write token.

Update procedure (from the repository root):

[source,bash]
----
# Install the deliberate tool version, not a moving release.
gh extension install github/gh-actions-lock --pin v0.2.0
bash scripts/update-actions-lock.sh
bash scripts/check-lock-sync.sh
bash scripts/tests/check-lock-sync-test.sh
bash scripts/tests/actions-lock-update-test.sh
git diff --check
git diff -- .github/workflows
----

If the extension is already installed, check its installed release and replace
it deliberately when necessary; do not assume `extension install` upgrades it.
Requires mikefarah/yq v4, jq, Bash, gh and authenticated access for regeneration.
Verification itself is offline.

The updater snapshots workflows and lock, rolls back failed updates, discards
verifier-only changes to *both* inputs, retains existing reusable dependency
records, restores exact job-level refs the generator cannot see, and keeps
SPDX first. It runs both upstream verification and structural closure checks.
A *new* reusable ref with no resolved dependency graph remains a failure: the
helper preserves established coverage, it does not invent a new commit or
pretend a missing graph is resolved. Resolve and review those records before
merging a reusable pin change, as was done for this PR. Existing records are retained only when reachable from the restored reusable
roots; unreferenced records are pruned and rejected by structural verification.

`annotate-clippy.sh` keeps clippy's exit status and emits compiler diagnostics
through the Checks API. The extra diagnostic job runs only after Rust CI fails;
it is not a second required build or an exemption for the original failure.

== Rollout acceptance criteria

. First repair malformed workflow/lock YAML; do not regenerate from an
  ambiguous duplicate-key document.
. For exact-pin consumers, bump governance to the validated compatibility SHA
  and resolve its complete dependency record/closure in the same change.
. Normalize headers, fix actual policy drift, and regenerate each repository's
  own lock. Do not copy rpa-elysium's complete lock into other repositories.
. Migrate the structural checker and regression controls through Standards and
  re-pin consumers; shared fixes do not reach SHA-pinned callers automatically.
. Inspect each repository's actual failed checks. Only upgrade async-trait or
  Wasmtime where that package/diagnostic is present; do not mass-edit unrelated
  Rust applications or relax their warnings/security gates.
. Run the positive and negative controls and all required checks on each
  rollout PR. Track inaccessible or unexamined repositories explicitly.
. Consider a repository propagated only after its change is merged and a
  default-branch run proves the required contexts pass. An issue or audit row
  alone does *not* satisfy this criterion.
